# Vault (OFF): expiry, refusal and delivery events reach `wait --filer` once, a keyed wait replays them, and `wait --into` delivers a Give once

Vault admission is OFF: `post --type vault` and vault feed items are refused, and no card or route shows vault items. What this covers is the private expiry, refusal and delivery events an ordinary filer wait reads, the keyed filer wait that replays one item, and the Give delivery into an approved folder that `wait --into` runs (not in `--help` while OFF). Records exist only through the built module (`dist/vault.js`), as `test/vault.test.mjs` creates them. Synthetic values only; never a real token, URL, `.npmrc` or board.

Work in a fresh scratch folder with its own `HOME`, `XDG_STATE_HOME` and `XDG_CONFIG_HOME`; delete it at the end.

| # | Step | Pass when |
|---|---|---|
| 1 | `wait $SCR/v/board.json --filer agent-a --timeout 0` before any vault state, also with `chmod 775 $HOME` | `NOT_FOUND`, empty stderr, no `$XDG_STATE_HOME` and no `.sign-off-vault-id` created |
| 2 | From the built module, `createVault` a Receive item for filer `agent-a` on that board, expiring in about 5 s; `serve` the board; start two `wait ... --filer agent-a --json` | Both keep waiting before the deadline; after it, exactly one prints `{"<key>":{"answer":"expired","label":"Vault item expired; request a fresh item.","close":"done","at":...}}` and exits 1; the other exits `NOT_FOUND` |
| 3 | `wait ... --filer agent-a` again, without `--json` | `NOT_FOUND`, no repeat; a TOON run on a fresh event shows `expired[1]{key,at}`, `error:` with the fixed sentence and `code: EXPIRED` |
| 4 | An answered ordinary item for `agent-a` beside an untaken expiry | The first wait returns the ordinary answer with exit 0; the next one returns `EXPIRED` |
| 5 | From the built module, `createVault` a Receive item for filer `agent-b` expiring in an hour, then `refuseVault` it; `wait ... --filer agent-b --timeout 0` twice | The first prints `refused[1]{key,at}`, `error: User refused this vault item; no value was delivered.` and `code: REFUSED`, exits 1 with empty stderr; the second is `NOT_FOUND` |
| 6 | `wait ... --key <agent-a key> --filer agent-a --json` twice, then the same with `--filer agent-b` and with no filer, `--timeout 1` | Both `--filer agent-a` runs print the same `expired` JSON and exit 1 (a replay, no marker); the other two are `TIMEOUT` with empty stderr |
| 7 | Write `$XDG_CONFIG_HOME/sign-off/vault-destinations` (0600) listing a 0700 folder `$SCR/tok`; from the built module `createVault` a Give item for `agent-a` with destination `$SCR/tok/api-token`, `depositVault` a synthetic value, then `deliverVault` it twice; also try a destination outside the listed folder | The first delivery returns `delivered` and leaves `$SCR/tok/api-token` at 0600 holding the value, with the record `delivered` and no payload; the second is `ALREADY_READ`; the outside destination is `DESTINATION_DENIED` with no record created |
| 8 | Make a second Give item for `agent-a` with destination `$SCR/tok/into-token`; start `wait ... --key <it> --filer agent-a --into $SCR/tok/into-token --timeout 10 --json`, then `depositVault` a synthetic value; run the same `--into` again; then `wait ... --filer agent-a --timeout 0` until `NOT_FOUND`; finally `--into` with no `--filer` but `SIGN_OFF_FILER=agent-a`, and `--into` on a fresh `XDG_STATE_HOME` | The first `--into` keeps waiting until the deposit, then prints `{"<key>":{"answer":"delivered","label":"Saved to the approved destination file.",...}}`, exits 0 and leaves a 0600 file holding the value; the second is `ALREADY_READ` (exit 1); the filer waits print each `delivered` event once (exit 0), then `NOT_FOUND`; no output names the destination; `SIGN_OFF_FILER` alone is `VALIDATION_ERROR` (exit 2); the fresh state is `TIMEOUT` with empty stderr and creates nothing |
| 9 | Grep every output and every file under the scratch HOME for the synthetic value and URL | No match; the board folder files (board, answers, seen) hold no vault key or filer routing |

`npm test` (`test/vault.test.mjs`) covers the same journey plus the concurrent take, folder scope, an expiry and a refusal for one filer (`EXPIRED`, then `REFUSED` on the next wait), held lock (one warning, `TIMEOUT` instead of `NOT_FOUND`, ordinary answers not delayed), Give delivery (the destination deny matrix, a list changed after create, pending, wrong filer or destination, a throw, a planted file, a tampered payload and a SIGKILL after the claim, racing deliveries), the delivery events (`delivery-uncertain` before `delivered`, one kind per poll, keyed replay without markers), `wait --into` (polling while pending, every final code, usage errors, racing, OFF silence), the keyed replay (wrong filer, no filer, a board row holding the key, a held lock), unsafe custody, malformed siblings and the all-or-nothing marker rollback.
