# Contract validator

Covers `validate`, `post --kind` and the shipped `fixtures/contract/` messages ([docs/contract.md](../../../../docs/contract.md)). Follow Isolation in `SKILL.md` and the Fresh shell in [axi.md](axi.md) first; this entry runs the packed tarball the way another tool's CI does.

## Steps

| # | Step | Pass when |
|---|---|---|
| 1 | In `$SCR/ci`: `npm init -y`, `npm install --no-save $SCR/sign-off-axi-<version>.tgz` | The folders under `node_modules/sign-off-axi/fixtures/contract/` are exactly the ones its `README.md` lists as shipped, no more and no fewer, and each holds 2+ `valid-*` and 3+ `invalid-*` files |
| 2 | `npx sign-off-axi validate node_modules/sign-off-axi/fixtures/contract/*/valid-*.json` | One `files` row per file with `ok` true; exit 0 |
| 3 | `validate` each `invalid-*.json` alone | `ok` false, an error naming the field in the file name, one `help` line; exit 2 |
| 4 | A message with `"recommend_value"` twice; one with `"schema": 2`; `validate --kind finding` on a valid ask | Exit 2 with `Remove the second "recommend_value".`, `Upgrade sign-off-axi`, and `is ask, not --kind finding` |
| 4b | `raise board.json --from feed.json` where the feed's one item is the report fixture `valid-full.json`; `list board.json --json`; `list board.json`; then the same with `"options": []` added, and `raise board.json --title` of 161 characters | The first prints `so the user can read it` and no answer hint; the item has `options: []` and `waiting: 0 of 1`; the other two exit 2 with `post an ask to get an answer` and `title is 161 characters, over 160` |
| 5 | `validate` a valid file plus a missing path; then `validate` with no file | Exit 1 with the missing row `cannot read: ENOENT`; then exit 2 with `error:`, `code: VALIDATION_ERROR` and `help:` |
| 6 | `npx sign-off-axi validate --expect-invalid node_modules/sign-off-axi/fixtures/contract/*/invalid-*.json`; then the same plus one `valid-*.json` | Exit 0; then exit 2 with that file `ok` true and the help `make it break the one rule its name gives` |
| 7 | `post board.json --kind ask --from <valid ask> --filer agent-41`, the same again, then `cat` the report fixture into `post board.json --kind report --from -` | `raised`, then `already waiting`; the board item keeps `kind` and `filer`; the report prints `so the user can read it` |
| 8 | `post --kind` refusals: stdin with no `recommend_value`; a valid ask with `--kind report`; a new title under the same key; the same ask again with `--filer agent-99`; `"filer"` other than `--filer`; `--title` beside `--kind` | Each exits 2 with one `help` line, the error starts with `stdin:` or the file name, and the board file is unchanged; each key conflict says `Post it under a new key` |
| 9 | `raise board.json --from feed.json` whose one item is `{"key":"pick","title":"Pick?"}` (no `kind`); the same feed with `post --replace` | Both exit 2: `feed.json: items[0] key pick: kind is required on a new decision`, help `Add "contract": 1, "kind" and "schema"` |
| 10 | `post board.json --kind evidence --from node_modules/sign-off-axi/fixtures/contract/evidence.v1/valid-media.json --filer agent-41`, the same again, the same with `--filer agent-9`; then `cat` `valid-run.json` into `post board.json --kind evidence --from -` | `signin-phone-2,1,1,...,posted`, then `already posted`, then exit 2 `already holds a different message`; `evidence/1/1.png` equals the fixture's `shot.png`; the stdin one is `update-2` with no media and the run stored as `evidence` |
| 11 | `open board.json`, then the Evidence area at 390 wide | Both updates show; `update-2` shows its Proof record with the four Checks lines (UNVERIFIED without `--evidence-root`) |
| 12 | An evidence message whose `media` is a symlink to a file outside its folder; a `--from` feed holding an evidence message | Both exit 2 and write nothing: `media[0] ... leads outside the message file's folder`; `new evidence is posted one at a time`, help `post --kind evidence --from` |
| 13 | `post gate.json --kind gate --from node_modules/sign-off-axi/fixtures/contract/gate.v1/valid-three-actions.json`, the same again, then the same message with another `run_id` from stdin | `dd-gate-a1b2c3d4,raised`, then `already waiting`, then exit 2 `already holds a different message`, help `Post it under a new key`; the board item keeps `kind` `gate` and its `run` |
| 14 | `open gate.json`, Waiting on you at 390 wide; pick **Fix first**; then `wait gate.json --filer done-done --json` | The card shows the title, about and the buttons Approve, Skip the judge and Fix first, Fix first marked as recommended; `wait` prints `fix` for `dd-gate-a1b2c3d4` |
| 15 | `post finding.json --kind finding --from node_modules/sign-off-axi/fixtures/contract/finding.v1/valid-apply.json`, the same again, then the same message with another `proposal` from stdin, then in a `raise finding.json --from` feed | `lfm-missing-env,raised` with a `wait --filer learn-from-mistakes` hint, then `already waiting`, then exit 2 `already holds a different message`, help `Post it under a new key`, twice; the board file is unchanged by the last two |
| 16 | `open finding.json`, Waiting on you at 390 wide; pick **Apply**; then `wait finding.json --filer learn-from-mistakes --json` | The card shows the title, about and the buttons Apply and Skip, Apply marked as recommended; `wait` prints `apply` for `lfm-missing-env` |
