# A board on a report

## Sub-features

- A board is data on a section of a guided report: `board` is optional, at most one per section, and holds either `shapes`, `arrows`, `zones` and `steps` or `mermaid` (a later slice), never both. A shape sits on a grid cell (`at`: column, row), an arrow names the two shapes it moves between by id, a zone names the shapes it surrounds, and a step names what the camera frames while its words show. Ids are shared by shapes, arrows and zones and are unique among them. The rules are in `src/board.ts`, whose geometry the page and the check share: a shape is one cell wide and its label fits on one line or breaks at a space or hyphen onto two.
- Report schema 6 (`src/contract.ts`): every field and rule of report 5 plus that board field on a section. The new `report init` default, and schemas 2 to 5 still load. A plan report's `design` part may carry a board where it needed a diagram. `docs/contract.md` (report schema 6) and `fixtures/contract/README.md` carry the form; the fixtures are `fixtures/contract/report.v6/`.
- The check, at post time and in `validate`, in plain Node with no page: the field rules; no line passes through a third shape; no line's label covers a shape or another label; no line crosses a zone's label; no label is longer than its line. It refuses the first rule broken with one fix line, and a refused board is never written.
- A removed id never comes back: `post` keeps what each earlier version of the report's boards dropped, refuses one that returns, and the fix names a new id, so an old mark can never land on a new shape (`src/cli.ts`, `retiredIds`).
- `report init <folder> --purpose <kind> --board` writes `<folder>/board.json` to fill, beside `report.json`; it is refused with `--plan` and with `--page`, which carry no board.
- The report shows the board where the agent explains it (`web/app-more.js`, `boardList`): a framed picture of the drawing — the same scene the canvas draws, as one SVG from `preview()` in `src/board.ts` (`GET /board/<key>/<section>/preview.svg`), so the picture, the canvas and the check cannot disagree — with one **Open board** entry, then the board's title and its list: the steps with their words, the shapes with their notes, the moves as `from → to` with the move's name and note, and each zone with the shapes it surrounds. The list stays under the picture, so a board reads in an export, on a read-only board and when the picture does not load. The picture is paper in either theme, as a whiteboard is, so it is never redrawn when the board's light or dark is flipped.
- An older sign-off-axi knows no schema 6, so it refuses one with "Upgrade sign-off-axi"; a board that already holds a schema 6 report keeps the data and shows that report under Notes until the upgrade, as it did at 0.10.2.
- The board page (`web/board.html`, served at `/board/<report key>/<section>`): a board opens full screen with sign-off's own bar — Back (the way out, into the report it was opened from), Previous, Next, Move, Fit, the step counter and the step's words — and the canvas filling the rest. The page reads only the scene the server checked and measured (`GET /api/board/<key>/<section>`, drawn by `scene()` in `src/board.ts`), so the page and the check cannot disagree about geometry. Every element the agent drew is locked, the editor is in view mode, and no control of the editor is in view: the journey fails above zero. Two fingers move and pinch the board, Move selects the hand tool, Fit and each step frame what they name, and a step's frame is made again when the canvas box changes under it. Read-only in this slice: there is no pen, no ink and no save.
- Back returns the person to the same place in the report. A board is a page of its own, so the report is drawn again on the way back: the block it was opened from and how far below the top of the report it sat are kept in the tab's session storage, and the block is put back on the report's first frames and again when a picture or the typeface lands. A report redrawn as the board changes does not jump back to the board: the kept place is used once per document.
- The canvas files are kept for a second open. `npm run build:board` names every canvas file for its content (`board-<hash>.js`, `chunks/`, `fonts/`), and only `board.js` and `board.css` keep their names, each carrying one line to the hashed file of its build; the server serves the hashed files `private, max-age=31536000, immutable` and those two entries, the page and the board's scene `no-cache` with an ETag. The service worker keeps the hashed files in a cache named for the build (`board-<BUILD>`, where `BUILD` includes the canvas's own loader) and serves them without asking the network; the page, its script and the scene are asked for again and answered 304. With the board out of reach, the kept copy draws. A rebuilt canvas names new files, so the next visit to the board's app drops the older `board-` cache and fetches the new build's files.
- The canvas ships inside the package: `npm run build:board` (`scripts/build-board.mjs`, esbuild) writes `web/board/` — the bundle, its chunks, the drawing font and `NOTICES.txt` — from the development dependencies `@excalidraw/excalidraw` 0.18.1, `react`, `react-dom` and `esbuild`, so the three runtime dependencies stay three. `prepack` runs it, so a published version carries the canvas and refuses to publish if the licence review fails.
- No request leaves the board: the page has a content security policy with no other host, the canvas asks this board for its files (`window.EXCALIDRAW_ASSET_PATH = '/board/'`), and `scripts/board/entry.js` keeps only same-origin sources on every font face the editor builds, so a font this package does not carry is never fetched from the library's CDN fallback. The journey fails on any request whose URL is not this board's.
- The licence and notice review (`scripts/board-licences.mjs`, run by the build): every package in the bundle is listed with the version, the licence id and the text of that licence, taken from the package's own licence file or, where a package carries none, from its repository, and each `NOTICE` file ships as it is. A file is charged to the innermost `node_modules/` it sits in, so a copy nested inside another package is named with its own version and holder, and each distinct licence text ships, so no package's holder is covered by another's. A licence id outside the allowed list, a package with no licence text anywhere, or no drawing font fails the build, so a package that fails is replaced or cut before anything ships. The drawing font is Excalifont, under the SIL Open Font License 1.1, and that licence text ships in the notices.

## Drive

- `done-done run board-cache` runs `board-cache-shots.mjs` at 390 and 1280 in light and dark, behind a proxy that keeps every request the server is asked for and the answer it gave: it posts a report 6 whose section holds the first real board, checks the block is a framed picture with one Open board entry, leaves the block at a known place and opens the board, then Back: the report returns to that same place and is scrolled down, not at its top. On a second open the server is asked for no canvas file at all, and the page, `/board/board.js`, `/board/board.css` and `/api/board/<key>/<section>` are each answered 304. With the board stopped, the board page draws every element from the kept copy. Then a real rebuild of the canvas from a copy of this checkout, served on the same origin: the older `board-` cache is gone, the new build has its own, and the new build's files are fetched. Captures: `board-cache-back.<theme>.<width>w.png` (the report, back where the board was opened from), `board-cache-offline.<theme>.<width>w.png` (the board with the board stopped), `board-cache.<theme>.<width>w.txt`, and the per-cell numbers under `board-cache-diagnostics/`. The same run proves the other two journeys this slice touches — `board-shots.mjs` for the report's block and its list, and `board-page-shots.mjs` for the board page's bar — measures the board's own cold first open again (the report's block must not add a request to it), and carries the approved-design capture at 1440, dark.
- `done-done run board` runs `board-shots.mjs`: `BOARD_CHECK=1` refuses each broken copy and accepts the three machine boards through the real `validate`, and runs `test/board.test.mjs` (post, a removed id coming back, `report init --board`, and a future schema refused with "Upgrade sign-off-axi"); then the reader at 390 and 1280 in light and dark posts the first real board and checks the picture and the list it draws: the framed picture of the drawing, the one Open board entry that opens this report's board, and the list of its steps, shapes, moves and zones under it. Captures: `board-check.log`, `board-cli.log`, `board-list.<theme>.<width>w.png` with its `.dom.json`.
- The three machine boards are `valid-task.json` (the task lifecycle, 14 shapes), `valid-lane.json` (lane delivery, 17 shapes) and `valid-line.json` (the first real board, the line after the plan, 17 shapes). Each broken copy is `invalid-<field>-<rule>.json` and breaks exactly one rule, and its name gives the field the refusal must name.
- The two faults found on the first real board, which the prototype check did not look for, are `invalid-arrows-line-across-zone-label.json` and `invalid-arrows-label-longer-than-line.json`. The corrected copies are the fixtures themselves: the lane board's zone label is shorter and two task-board move names are shorter than the record's.
- `done-done run board-page` runs `board-page-shots.mjs` at 390 and 1280 in light and dark: it posts a report 6 whose section holds the first real board through the real CLI, follows the report's **Open board** into the board page, and checks that every shape, line and zone is on the canvas and locked, that no control of the editor is in view, that the bar is Back, Previous, Next, Move, Fit with Back returning to the report, that nothing scrolls sideways, that a real two-finger pinch changes the zoom, that Fit frames the whole board again, that every step frames all its elements in view with its own words and counter, that Previous stops at the first step, that no request names another host, and that the console holds no error. Captures: `board-page.<theme>.<width>w.png`, `board-page-step.<theme>.<width>w.png`, the per-frame numbers under `board-page-diagnostics/`, and `board-page-steps.json`.
- `done-done run board-notices` runs `board-notices-proof.sh`: the real build and its review, the notices copied as `NOTICES.txt` with their opening as `notices-index.txt`, `nested-packages.txt` (every package that sits inside another package's own `node_modules/`, each named in the notices with its own version and the holder line of the text shipped for it) and the notices test as `board-notices.log`, then the Designs capture at 1440, dark.
- `node --test --test-global-setup=./test/temp-folder.mjs test/board.test.mjs` is the CLI regression. `validate --kind report <fixture>` names the board rule in its one fix line. `test/board-notices.test.mjs` drives the canvas build's licence review: the real build passes with every package and the font listed, every package the esbuild metafile holds (read from its input paths and each package's own `package.json`, nested copies included) is named in the notices with its own licence text, and the review refuses a package naming a licence outside the allowed list, one that names none, and one that carries no licence text anywhere.
