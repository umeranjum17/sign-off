# Tickets

Tickets are not kept on the board. The Tickets screens, `sign-off-axi ticket` and the board's `/api/tickets` routes read and write them only through the ticket adapter: one executable, named by `SIGN_OFF_TICKETS_ADAPTER`, called as `adapter <operation>` with one JSON request on stdin and one JSON response on stdout (`docs/ticket-adapter.md`). The board writes no ticket file and keeps no cache; every read is another call, and a failed call is shown as the adapter said it.

## Sub-features

- `ticket`: no flag lists every ticket (`--json` gives them as the adapter sent them, with the keys of the cards that name each); `--id` shows one with its cards; `--fields` prints the adapter's `describe`; `--create --set title=...`, `--id <id> --rev <rev> --set k=v --unset k`, `--history` and `--text <words>` write or read through the adapter. A write carries `--op-id` (the CLI makes one) so a repeat is safe. `--id <id> --comment '<json>'` still records a comment the person made in the fleet dashboard, in `<board>.ticket-comments.jsonl`.
- `--ticket <id>` on every way a card gets in (`raise`, `post`); it is a loose reference, never checked at post time. A card's screen shows a Ticket row with the id, which opens the ticket's page; the ticket's page lists the cards that name it.
- The Tickets screen (`#tickets`) is a board in the calm look the captain picked on 16 Nov (option 2): one column for each status the adapter lists, empty or not (its own words and order, made readable by one rule where `describe` gives no label; a status `describe` does not list follows them when a ticket has it, none otherwise; a column with no ticket keeps its place and count and says Nothing here.), cards newest change first, each with the title, the ticket's own `id` in small monospace (a long hash id shortened in the middle on the card only) and one small line: its project (the adapter's optional read-only string field `project`, first on the line, none when the ticket has none), who has it and when it changed, set off by dots (a long project gives way with an ellipsis at half the line, a long assignee first, the time stays whole and on a card narrower than 215px says `9 min ago` for `Updated 9 min ago`); on a phone one column at a time with a tab for each (its mark and count, the name of the one in view). The board shows what the adapter lists and holds no word for a closed ticket. Its head has the filter drawn from the fields `describe` gives words for, New ticket, and links to **Epics** (`#epics`, tickets that others name as `parent`, one card each with the tickets under them and how they stand) and **Activity** (`#activity`, the `history` of the tickets that changed last, naming who made or moved each one and narrowing to one person with its Person pick; "This backend keeps no history." when `describe` lacks `history`).
- An epic's page (`#epics/<id>`): the epic, New ticket in this epic, and the tickets under it grouped by the status words the backend gave. A group of tickets is a ticket others name as `parent`, so a ticket under no epic sits in the No epic group and the board never guesses which `kind` means an epic.
- A ticket (`#ticket/<id>`) opens as a sheet over the board (from the foot on a phone, from the right edge on a desk): its whole id with a Copy button (it says Copied, and the clipboard holds exactly the id), the title, where it stands, its facts (the project first where the ticket has one, then those `describe` names), the body, every key of `extra` and every top-level key the board does not know (the project is one it knows) under More fields, links, the tickets under it, the cards that name it, its history as a timeline and a comment box where the backend has `comment`. A ticket the list does not carry (a card names it) is read on its own and opens in the same sheet; one that cannot be read says so.
- New ticket (the round + in the header, `c` on a desk) and Edit are drawn from `describe`; an edit sends only the changed fields with the `rev` that was read. `invalid` marks the fields the adapter named and keeps every word typed; `conflict` shows the adapter's current version beside the person's ("Now", "Yours") with Save over theirs and Discard mine. There is no delete.
- A failed read shows the adapter's `code: message` with Retry and no rows. A list the adapter does not vouch for (`complete` not true) is `incomplete`, with no rows, never a partial list.
- Where a status, kind or label word comes from: the adapter. The board holds none. Where `describe` gives a status or kind (any `enum`) no label, the board shows its value by one rule: a lowercase word of letters and digits joined by `_` or `-` gets spaces and a capital first letter (`in_progress` reads In progress, `on_hold` On hold, `task` Task), any other word as it is; an assignee, a label or a parent is never changed. It is one function (`tkWord`), used by the column heads, the sheet, the filter and the epic rows.

## Drive

`node .agents/skills/done-done-verify-sign-off/tickets-board-shots.mjs <folder> <light|dark> <390|1440>` (journey `tickets-board`, one width and theme per run, or all four with none), after `npm run build`. It serves a throwaway board against the stand-in adapter holding fourteen tickets (short ids, one long hash id, an epic with three tickets under it, two people, two projects and one long project name, a long assignee, a ticket whose project is null and one with no such key, three statuses the stand-in lists and two it does not, one of them `on_hold`) and captures the board, a Kind filter that leaves two columns empty (their count 0 and Nothing here.), on a phone the third column's tab, a ticket's sheet with its whole id, Copy turned to Copied with the text read back from the clipboard, a ticket with history and More fields, a failed read and an incomplete list, one png each, with `steps.json`; it fails on a layout lint fault in any frame. `DEMO_PAGE=<the option-2 demo's html>` also captures the demo at the same size and theme and writes `side-board` and `side-sheet` frames with the demo on the left and the build on the right. Look at every capture: the column heads are the stand-in's own words made readable (Stage 1, On hold), each card carries its id under the title (the long one shortened with an ellipsis in the middle) and its project first on the small line below (none for the two tickets without one; the long project and the long assignee end in an ellipsis and the time stays whole), the sheet shows the id whole and the project first among its facts, a failure reads `unavailable:` with the adapter's message and a Retry button and no cards.

`SIGN_OFF_TICKETS_ADAPTER=<a real adapter> [TICKETS_REAL_BREAK=NAME=VALUE] node .agents/skills/done-done-verify-sign-off/tickets-real-shots.mjs <folder> [light|dark] [390|1440]` (not a `.done-done.yaml` journey: it needs a real adapter and its store, which CI does not have), after `npm run build`. It holds no ticket and no backend word: it asks the adapter its `describe` and `list`, serves a throwaway board on that adapter (with the adapter's own environment, e.g. the variable that names its store, and the system python first on `PATH`, because a version manager's shim reads the real HOME), and checks the board against the adapter's answer: a column for each status the adapter lists (and each it lists a ticket under), empty or not, in the adapter's order with its readable word, no underscore in a head, every ticket on a card with its own id and title, its assignee as given and its project as given (no label where it has none), a sheet with the whole id, status, project, kind, assignee and parent as given. It captures `board`, `sheet` and (with `TICKETS_REAL_BREAK=NAME=VALUE`, which starts a second board whose adapter has that one variable changed so it cannot read its store) `failure`, one png each per theme and width, with a `steps.json` per cell. A real store answers in seconds and a loaded host can make a read outlast the board's 20 seconds: the run then taps Retry (twice at most) and fails with the board's own words on a second miss, keeping a `timeout` frame of what the board said. When an adapter's `list` cannot be read in time, `SIGN_OFF_TICKETS_ADAPTER=test/support/ticket-adapter-describe-from.mjs` with `TICKET_DESCRIBE_FROM=<that adapter>` (and the environment it reads its store from) drives the same journey over that adapter's own `describe` and fourteen stand-in tickets spread over the statuses it lists (ids `stand-in--NN`, a project field only where its `describe` has one); say so wherever those frames are shown, because the rows are not real. The frames show the real tickets: write them outside the repository.
